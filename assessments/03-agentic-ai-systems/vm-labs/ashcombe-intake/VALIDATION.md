# `ashcombe-intake` — validation record

Run on macOS, CPython 3.14.6 in a virtualenv with `pymupdf` 1.24.14, against the
pack's own harnesses. Numbers are observed.

## 1. Reference solution

    PY=<venv>/bin/python bash test-cases/scripts/run-all.sh
    SCORE: 50/50   (passed 5, failed 0)
    slowest test case: 1s   (portal limit is about 120s)

Check 2 spends **29 cost units against a budget of 29** — the minimum the stated
routing allows.

## 2. Alternative correct shapes — all 50/50

- `alt1_blocks_triage` — triage counting text blocks rather than characters.
- `alt2_parts_chunker` — the chunker accumulating a list of parts.
- `alt3_ifelse_routing` — the routing rule as a branch rather than a table.
- `alt4_outdir_seen` — "already done" read off the artefacts rather than the
  ledger.
- `alt5_manifest_worker` — an extra `_manifest.json` and a prepared work list.

`alt5` caught a real over-strict assertion during authoring: two checks required
`out/` to hold *exactly* one file per document, which failed a worker that
writes its own manifest. Both now require each document to have an artefact and
say nothing about extras.

## 4. Fabrication probe

- `_cheat_no_parse` — invents plausible elements instead of calling the parsing

## 5. The corpus

Generated by `tools/make_corpus.py` with PyMuPDF, and it is real:

- scanned documents are rendered to a grayscale JPEG at 72 dpi and re-wrapped,
  so they carry **no text layer** — `page.get_text()` returns 0 characters,
  measured;
- native pages carry 200-400 characters, measured;
- the mixed documents carry text on page 1 and none on page 2.

The first draft rendered scans as full-colour PNG at 110 dpi, which produced
**3.5 MB per document and a 23 MB `corpus.py`** — far too big to ship inside a
service file. Grayscale JPEG brought that to 95 KB total.

`build.sh` re-hashes the three shipped documents against the plans the desk
holds and refuses the build if they have drifted, because regenerating the
corpus changes every hash.

## 6. Ordering matrix

    ./validation/permutations.sh
    rows: 7   failures: 0

Rows: starters untouched (0/50) · written but never run (50/50) · learner
drained their own spool first (50/50) · grading killed after three checks
(30/50) · graded a second time (50/50) · learner ledger deleted (50/50) ·
learner `out/` removed (50/50). Every row that can also asserts the learner can
still drain their own spool afterwards, and all of those passed.

**The matrix earned its keep here.** Rows 3 to 7 initially failed at 40/50: the
desk keeps a record per run id, the check run ids are fixed, and a second
grading run on the same VM therefore saw every document parsed twice. Each check
now clears its own run before it starts counting. The happy path was green
throughout.

## 6b. The VM end-to-end row — with nothing overridden

    ./validation/vm-e2e.sh            # cold ubuntu:25.04 container
    ./validation/vm-e2e.sh --here     # as root on the VM itself

    failures: 0   (setup 6s foreground)

Provisions a cold root filesystem from `dist/Setup.zip`, submits the untouched
starter straight away, writes the reference solution as `user`, submits again,
and asserts the learner still owns their project. **Nothing is overridden** —
`LAB_DIR`, `DESK_URL` and `DESK_BIN` keep the values the checks ship with.

Observed: setup returns in **6s** of foreground time; the desk answers
`/health` straight out of provisioning; the untouched starter scores 0/50 with
every check naming the starter; the reference solution then scores **50/50**;
nothing under `/home/user` is root-owned after two grading runs. The first
submission takes ~25s, all of it `ensure_deps` waiting on the detached pymupdf
install; the second takes under a second.

This row exists because sections 1 to 6 above were all blind to two defects
that made the lab score nothing on the portal, and blind for the same reason:
`run-all.sh`, `sweep.sh` and `permutations.sh` every one export `LAB_DIR`,
`DESK_URL` and `DESK_BIN`, so **the values the VM actually uses had never been
exercised once**.

## 6c. Production defects found on the first portal run, and their fixes

Symptom: submitting on the portal rendered an empty *Test Case Results:* list —
a green tick, no rows, no messages, whatever the state of the project.

**The cause of the empty panel is the judge's ERR trap, not the desk.** An
earlier revision of this section blamed the dead desk below and was wrong: a
dead desk produces five *visible* failures. The blank panel has its own cause,
already recorded for seven other packs in `vm-labs/DESIGN-NOTES.md` under
"the judge's ERR trap silently voided every submission" — a fix this pack never
received.

The platform helper at `/usr/local/bin/judge/test/common.sh` ends with

    trap 'handle_script_error $LINENO $? "$BASH_COMMAND"' ERR

and sourcing it installs that trap **inside the check's own shell**. An ERR trap
fires on any non-zero simple command regardless of `set -e`, a deliberate
`return 1` from a guard included; its handler prints an internal error and exits.
`main.sh` grades `tail -n 1` of stdout+stderr, so the verdict is discarded, the
last line matches neither status, and the submission is posted with
`evaluated: false` and **no results array**. Hence a panel with nothing in it.

Reproduced side by side on the refusal path, against a faithful replica of the
real helper:

    with `trap - ERR`      { "status": "failed", "message": "these still hold the untouched starter: ..." }

    without it             { "status": "failed", "message": "these still hold the untouched starter: ..." }
                           INTERNAL_ERROR: An error occurred at line 418: 'return' exited with status '1'

**Why every harness said 50/50 for a pack that scored nothing.** Two reasons,
both now closed:

- The local `common.sh` was a *convenience stub* — `echo "RESULT:$1 | $2"`, no
  ERR trap, no JSON. A stub easier to satisfy than the real helper makes
  validation worthless. It is now a byte-for-byte copy of the replica used by
  the seven migrated packs.
- `run-all.sh` took the **first** `RESULT:` line anywhere in the output, and
  `permutations.sh` grepped for `RESULT:success` anywhere. Both now read the
  **last** line and parse it as JSON, and both fail a row whose last line is not
  a verdict — the score alone cannot see this bug, because a voided verdict and
  an honest failure both score zero.

Confirmed: with `trap - ERR` removed, `permutations.sh` row 1 reports all five
checks *ended on a non-verdict* and the matrix goes red; the reference solution
still scores 50/50 in that state, which is exactly why the happy path never
caught it.

The fixes in the preamble: `trap - ERR` and `set +eE` immediately after
sourcing the helper, and `exec 2>>/tmp/ashcombe_tc${TC}.err` so that a stray
line on stderr cannot become the graded line either.

### Three more defects found while reproducing, all real

Reproduced in a cold container, where the first is plain in
`/var/log/ashcombe-desk.log`:

    ModuleNotFoundError: No module named 'corpus'

1. **The desk was installed without the module it imports.** Phase 4 of the
   setup template inlined `service/intakesvc.py` and not `service/corpus.py`, so
   `/opt/ashcombe-svc/` held a desk that died on its first import. Provisioning
   ended in `LAB NOT READY - desk-down`, and all five checks reported *the
   intake desk is not reachable*. With the desk dead, a submission also spends
   ~90s per attempt in `ensure_deps`/`ensure_desk`, which is what turns "five
   failures" into "no output at all" if the portal caps the run.
   Fixed: phase 4 now writes `corpus.py` as well, and then imports it as a
   check.
2. **The checks read another lab's project.** `LAB_DIR` defaulted to
   `/home/user/ashcombe-rubric`; setup builds `/home/user/ashcombe-intake`. Even
   with the desk alive, every check would have reported a missing project.
   Fixed in `gen_tests.sh`, which is the source of the five scripts.
3. **The systemd unit had no `ExecStart`.** `Environment=PYTHONPATH=${SVC}\nExecStart=...`
   was written into an unquoted heredoc, where `\n` stays two literal
   characters — so the unit carried one malformed `Environment=` line and no
   `ExecStart` at all. `systemctl enable --now` always failed and the desk only
   ever came up through the `nohup` fallback, unsupervised. Fixed to a real
   newline.
4. **`jq` arrived too late to print a verdict.** The platform helper builds its
   one line with `jq -n`, and `jq` was installed by the *detached* job — which
   finishes well after the learner can press Submit. A check running before it
   lands cannot emit a verdict at all: another empty panel, from a different
   direction. Setup now installs `curl` and `jq` in the foreground (+13s, to a
   20s total against a 95s budget) and the build refuses a setup script that
   does not.
5. **The fix for 4 broke the readiness gate, and the harness caught it.**
   `ensure_deps` treated "curl and jq are present" as a proxy for "the detached
   install has resolved". With those two now in the foreground the proxy was
   always true, so a check could run before PyMuPDF existed and then report
   *intake/triage.py does not import* — blaming the learner for a half-built VM.
   `ensure_deps` now waits on the readiness file and falls back to the tool
   check only after the wait, and a new `require_pdf_lib` guard reports a
   missing PyMuPDF as an environment fault naming `deps.log`, not as a wrong
   answer. Caught by `validation/vm-e2e.sh` on the run immediately after the
   `jq` change, which is the whole reason that harness exists.

`build.sh` step **[3/6]** now refuses any check that does not carry `trap - ERR`,
`set +eE` and an `exec 2>>` redirect, and refuses a `common.sh` that is not the
replica. Step **[3b/6]** would have caught the rest before the zips were
staged: the setup script's `PROJ` must equal every check's `LAB_DIR`
default; both desk modules must be written; the unit must carry an `ExecStart`
of its own with no literal backslash-n; and the desk lifted back out of the
generated setup script must answer `/health` from a directory holding nothing
else.

Proven negatives, each watched failing before the fix was kept:

- defects 1 and 2 reintroduced → `validation/vm-e2e.sh` reports **4 failures**
  and prints the `ModuleNotFoundError` from the desk log;
- `trap - ERR` removed → `permutations.sh` row 1 reports five checks ending on
  `INTERNAL_ERROR` and the matrix goes red, while the score stays 0/50 exactly
  as a correct refusal would.

### The same defect classes in sibling labs

Audited across all fifteen VM labs:

- **The ERR trap: eight packs were never migrated.** `caldon-wire`,
  `lambwell-market`, `marlow-depot`, `orenford-newsroom`, `redcliffe-signals`,
  `thistledown-mill` and `westmere-claims` carry `trap - ERR`, `set +eE`, the
  stderr redirect and the replica `common.sh`. This pack did not, and neither do
  `ashford-grid`, `kilnbrook-foundry`, `larkspur-transit`, `bellhaven-rubric`,
  `caverly-trust`, `norbury-flow` or `pelham-approvals` — every one of them will
  render an empty panel on any refusal path. This pack is now migrated; the
  other seven are not.
- **`LAB_DIR`: two more carried it.** `norbury-flow` read
  `/home/user/norbury-rubric` and `pelham-approvals` read
  `/home/user/pelham-rubric`. Both fixed and rebuilt.
- The un-inlined-module and literal-backslash-n defects are unique to this pack.
